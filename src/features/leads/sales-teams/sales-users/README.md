# features/leads/sales-teams/sales-users — مستخدمين السيلز

> **Documentation update:** 2026-10-16 02:40 (Africa/Cairo) — الفولدر اتعمل.

صفحة `/LeadsCenter/teams/users` (عنصر "مستخدمين السيلز" في سايد بار فرق السيلز). بتعرض المستخدمين مرتبين بالأولوية،
وبتعدّل **الأولوية، المدير، الدور، النوع، الحالة** من الجدول مباشرة، وكل حقل بيتحفظ لوحده.

## الصفحة
- **تابين:** "السيلز" (المستخدمين اللي `type = sales`) و"كل المستخدمين". لو مفيش حد نوعه sales بتظهر رسالة ولينك لكل المستخدمين عشان تغيّر نوع اللي شغالين سيلز.
- **أرقام:** مستخدمين السيلز، النشطين، اللي ليهم أولوية، والأولويات المكررة.
- **بحث** (الاسم، البريد، اليوزر، التليفون، الدور، النوع) و**فلتر الحالة**.
- **الجدول** (`DataTable` المشترك، `tableId = sales-teams-users`): الأولوية · المستخدم · المدير · الدور · النوع · الحالة.

## الأولوية (رقم ترتيب فريد، 1 الأول)
- الترتيب: اللي ليهم أولوية (1، 2، 3…) الأول، وبعدهم اللي أولويتهم 0 أو فاضية بالاسم (`sortByPriority`).
- **تعديل الرقم:** بيتحفظ بـ Enter أو لما تسيب الخانة؛ Esc بيلغي. لو الرقم مع مستخدم تاني بتظهر رسالة وزرار **"بدّل مع X"**.
- **سهم لفوق / لتحت:** بيبدّل الأولوية مع اللي قبله / بعده في القائمة الظاهرة.
- **ترتيب تلقائي:** بيدي المستخدمين الظاهرين 1، 2، 3… بنفس ترتيبهم (بعد تأكيد)، وبيعدّل اللي رقمه هيتغير بس (`renumberPlan`).
- **التكرار:** تنبيه فوق الجدول و"أولوية مكررة" جنب كل مستخدم.
- عشان الباك لو بيمنع التكرار ميرفضش: أي مستخدم رقمه الحالي هو الرقم الجديد لحد تاني في نفس العملية بيتصفّر (0) الأول (`priorityUpdateSteps`). التبديل = 4 طلبات.

## الحقول التانية
| الحقل | الإدخال | المبعوت |
|---|---|---|
| المدير | قايمة المستخدمين (غير نفسه) أو "بدون مدير" | `manager_id` (رقم أو `null`) |
| الدور | نص مع اقتراحات (admin, manager, team_leader, sales, agent + القيم الموجودة) | `role` (فاضي = `null`) |
| النوع | نص مع اقتراحات (sales, internal, support, marketing, external + الموجودة) | `type` |
| الحالة | مفتاح | `active` = 1 / 0 |

كل طلب بيبعت الحقل اللي اتغير **ومعاه `name` و`email` و`username` (و`phone` لو موجود) زي ما هم**، لأن دالة التعديل غالبًا بتطلبهم.
مبنبعتش `password` ولا `team_id` (`buildUserFieldPayload`).

## ثغرات معروفة
- مستنيين تأكيد الباك (E3): هل التعديل بيقبل حقل واحد من غير `name`/`email`؟ هل `active` مقبول في التعديل؟ هل الأولوية فريدة على كل المستخدمين ولا على السيلز بس؟

- الصلاحيات على الباك؛ الصفحة متاحة لأي حد بيشوف القسم.
