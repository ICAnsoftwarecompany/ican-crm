## 2. الخطوات بتمشي مع نوع الصنف (`utils/createSteps.js`)

| | من غير نوع (يدوي) | بنوع |
|---|---|---|
| البيانات الأساسية | ✓ | ✓ + كارت "النوع ده هيملالك إيه" |
| المخزون والوحدات | ✓ تضيف الوحدات بنفسك | ✓ متملية من وحدات النوع — **بتختفي** لو النوع `unique_unit` (كل قطعة فريدة) |
| التفاصيل | ✓ مفيش قدرات؛ "البيع بينشئ" + حقول حرة | ✓ حقول قدرات النوع (الفاضي = افتراضي النوع) + البيع بينشئ + حقول حرة |
| الحاجات المرفقة | ✓ تضيفها بنفسك | ✓ متملية من حاجات النوع المرفقة |
| القطع | ✓ بتشرح إن القطع محتاجة نوع + زرار "نوع سريع" | بتظهر **بس** لو النوع فيه سيريال / وحدات فريدة / دفعات |
| المراجعة | ✓ | ✓ |

- من غير نوع العميل بيعدي على **كل** الخطوات ويملاها يدوي. ولما يختار نوع، الخطوات اللي مالهاش لازمة بتختفي، والباقي بيتملى منه.
- لو الخطوة الحالية اختفت (مثلًا اختار نوع من غير قطع وهو واقف على القطع)، الصفحة بتنقله على اللي قبل المراجعة.
- **"التالي"** بيتحقق من الخطوة الحالية. الضغط على خطوة قدام بيتحقق من كل اللي بينهم ويوقف عند أول غلط. الرجوع لورا مسموح دايمًا.
- **ملء البيانات من النوع:** وحدات النوع وحاجاته المرفقة بتتملى لوحدها (`applyTypeDefaults`، شرحه في
  [item-type-wizard/README.md §7](../item-type-wizard/README.md)). السطور اللي العميل عدّلها مش بتتلمس أبدًا، وبيظهر تنبيه بيقول اتملى إيه.
- لو النوع خطة أو باقة وجاي من `?item_type=`، الـ `kind` بيتظبط عليه.

### 2.1 إضافة خدمة (`/products/new?kind=service`) — 2026-10-15 13:30 (Africa/Cairo)

| | الخدمة |
|---|---|
| الخطوات | **الخدمة ← بتتنفذ إزاي ← الخدمات المرفقة ← المراجعة** (`SERVICE_CREATE_STEPS`)، بنوع أو من غير نوع |
| اختيار النوع (منتج/خطة/باقة) | **مش ظاهر**: الـ kind ثابت `service` (`allowedKinds=['service']`) |
| المخزون والوحدات | مفيش خطوة. وحدات النوع **مش بتتنسخ** (`applyTypeDefaults(..., { withUnits: false })`)، و`buildCreatePlan` بيشيل `units` |
| القطع | مفيش خطوة: قدرات السيريال والوحدات والدفعات خاصة بالمنتجات |
| الحاجات المرفقة | **خدمات بس** (`RelationRowsEditor onlyKind="service"`)، وأزرارها "خدمة ضمن السعر" و"خدمة اختيارية" |
| كارت النوع | بيوري الخدمات المرفقة بس (من غير وحدات ولا قطع) |
| النصوص والشرح | `productSetup.service.*`: عناوين الخطوات، والشرح، وشرح الحقول، والرسايل (`utils/stepCopy.js` بيختار المفتاح حسب الـ kind) |
| الإضافة السريعة | نفس الصف، من غير وحدات النوع، وشرح الحقول بتاع الخدمات |
| درج التعديل | تبويب "المخزون والوحدات" مش بيظهر للخدمات |

ومعاها كمان: **أنواع الخدمات مالهاش خطوة وحدات** في صفحة النوع (`supportsUnits` بقت للمنتجات بس)، وقوالب الخدمات اتشال منها
اقتراح الساعة والزيارة.

## 3. الوضع التعليمي (الشرح)

- زرار **"إظهار / إخفاء الشرح"** في الهيدر، مفعّل افتراضيًا ومتحفظ (`product-tutorial`).
- لوحة على الجنب (`components/common/TutorialPanel` بـ `guideKey = productSetup.steps.<step>.guide`) فيها:
  1. الخطوة دي بتاعة إيه، والنقط اللي هتعملها.
  2. **`StepTypeNote`**: النوع غيّر إيه في الخطوة دي (مثلًا "النوع تكييفات ملالك 1 وحدة"). من غير نوع بتظهر جملة "يدوي".
  3. شرح الحقل اللي العميل واقف عليه بالماوس أو داخل عليه بالكيبورد.
- كل حقل في البيانات الأساسية جنبه ⓘ، والنصوص في `productSetup.help.*`. والعلامات دي بتظهر كمان في درج تعديل المنتج.

## 4. الإضافة السريعة (`QuickAddMode` + `hooks/useQuickAdd.js`)

- **checkbox "إضافة سريعة"** في الهيدر، ومتحفظ لكل نوع لوحده (`product-quick-add-product` / `-service`).
- الفورم صف واحد: **الاسم، الفئة (+ فئة سريعة)، السعر**، ونوع صنف اختياري. **Enter بيحفظ**:
  - طلب `POST /product/create` عادي (`buildQuickProduct`). لو فيه نوع متختار، وحداته الافتراضية بتتبعت مع الطلب.
    الحاجات المرفقة والقطع مش بتتبعت، ومكانها الإضافة الكاملة أو صفحة الصنف.
  - بعد الحفظ الاسم والسعر بيفضوا، والفئة والنوع بيفضلوا، والمؤشر بيرجع على الاسم عشان يكمّل اللي بعده.
  - التحقق: الاسم إجباري والسعر رقم 0 أو أكتر.
- **القائمة الجانبية** (`QuickAddSidebar`) فيها تبويبين:
  - **"اتضافت دلوقتي"**: اللي اتحفظ في الجلسة دي، الأحدث فوق.
  - **"كل المنتجات"** أو **"كل الخدمات"** حسب الصفحة، من `/product/data`، ومعاها حالة التحميل والخطأ.
  - كل سطر بيفتح صفحة الصنف.
- تحت الفورم بيظهر مسار الفئة المختارة برضه.

## 5. النوع السريع والفئة السريعة

**النوع السريع** (`item-type-wizard/components/QuickItemTypeDialog`) بيتفتح من 3 أماكن:
- جنب اختيار النوع.
- من كارت "مفيش نوع".
- من خطوة القطع.

فيه الاسم، وكود اختياري، وقالب جاهز اختياري. بعد الحفظ النوع **بيتختار على طول** والبيانات بتتملى منه.

**"فتح صفحة النوع الكاملة"** من نفس النافذة:
1. اللي اتكتب في المنتج بيتحفظ **مسودة** (`saveDraft`).
2. بيفتح `/products/item-types/new?kind=…&returnTo=/products/new?draft=<id>`.
3. بعد حفظ النوع بيرجع على `/products/new?draft=<id>&item_type=<id>`: المسودة بترجع زي ما كانت، والنوع الجديد متختار.

**الفئة السريعة** (`components/QuickCategoryDialog`):
- فيها الاسم، والفئة الأب (افتراضيًا الفئة المختارة حاليًا)، والوصف.
- الحفظ `POST /api/tenant/category/create` بنفس body صفحة الفئات (`name`, `desc`, `type` = product/service, `category_id`, `status: 1`).
- بعد الحفظ الفئة بتتختار على طول. الصورة والحقول الإضافية مكانهم صفحة الفئات.

## 6. تفاصيل الفئة ومسارها (`components/CategoryDetails` + `utils/categoryPath.js`)

- أول ما فئة تتختار، بيظهر **المسار** (الجد › الأب › المختارة)، وكارت لكل مستوى فيه:
  - الاسم ومستواه (المختارة / الأب / فوقها).
  - مفعّلة ولا لأ، والوصف.
  - عدد الفئات الفرعية، وحقولها الإضافية.
- `categoryPath(tree, id)` بيمشي في شجرة `/category/data`. الشجرة بتتجاب من الفئات الـ flattened اللي `_depth = 0`.
- **الحقول الموروثة:** الحقول الإضافية بتاعة كل المسار (`inheritedFieldNames`) بتتقترح في خطوة التفاصيل كبيانات إضافية للمنتج.

## 7. المسودات (`hooks/useProductDrafts.js` + `utils/productDrafts.js`)

- **إمتى بتتعمل:** زرار "حفظ كمسودة" في الهيدر، أو تلقائي قبل "فتح صفحة النوع الكاملة".
- **التحديث:** طول ما الصفحة مفتوحة على مسودة، كل تعديل بيتحفظ فيها بعد نص ثانية.
- **المسح:** المسودة بتتمسح أول ما الصنف يتحفظ.
- **بيتحفظ فيها:** الفورم كله ما عدا **الصورة**، والبيانات الإضافية، والحاجات المرفقة، والقطع، والخطوة اللي وقف عندها.
  ولو كان فيه صورة بيظهر تنبيه يختارها تاني.
- **فين:** في المتصفح (`ican:catalog:product-drafts`)، وبحد أقصى 20 مسودة، والأحدث فوق.
  - بتتكتب في التخزين على طول مش جوه state update، عشان الحفظ والانتقال لصفحة النوع بيحصلوا في نفس اللحظة.
  - لو التخزين مقفول بتشتغل في نفس التبويب بس.
- **العرض:** `DraftsPanel` في أول خطوة، بمسودات الصفحة دي بس (مسودات الخدمات في صفحة الخدمة والباقي في صفحة المنتج)،
  ومع كل مسودة "كمّل" (بيفتح `?draft=<id>`) و"احذف".

## 8. الحفظ (`hooks/useCreateSubmission.js`)

الترتيب ثابت زي الكولكشن، مفيش أي endpoint جديد:
1. `POST /product/create`: المنتج، ومعاه الوحدات البديلة.
2. `POST /products/{id}/relations`: لكل حاجة مرفقة.
3. `POST /products/{id}/instances`: القطع.

اللي نجح بيتسجل، فلو حاجة فشلت "إعادة المحاولة" بتكمّل من عندها ومش بتعمل المنتج مرتين.
الخدمات مش بتبعت مخزون، والأنواع اللي فيها سيريال أو وحدات المخزون بتاعها بيتحسب من القطع.

## 11. حاجات ناقصة

- المسودات في المتصفح بس: مش بتنتقل لجهاز تاني، والصورة مش بتتحفظ. لو اتعمل endpoint للمسودات تتنقل له.
- الإضافة السريعة مش بتبعت الحاجات المرفقة بتاعة النوع.
- الفئة السريعة من غير صورة ولا حقول إضافية.
- الصفحة متجربتش بالعين ولا على سيرفر حقيقي (RTL/LTR، الوضع الغامق).
