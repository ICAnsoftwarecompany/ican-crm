## 3. السلايدر (جولة في أجزاء النظام)

### الشرائح الحالية

| # | المعرّف `id` | الجزء | العنوان |
|---|---|---|---|
| 1 | `overview` | ICAN CRM | كل عملائك وكل قنواتك في مكان واحد |
| 2 | `customers` | إدارة العملاء | من أول رسالة لحد ما العميل يشتري |
| 3 | `teams` | الفرق والتوزيع | كل ليد يوصل للشخص الصح فوراً |
| 4 | `calls` | المكالمات والاجتماعات | مكالماتك واجتماعاتك في تقويم واحد |
| 5 | `conversations` | المحادثات | رد على كل القنوات من غير ما تسيب النظام |
| 6 | `campaigns` | الحملات الإعلانية | من الإعلان لحد الليد من غير نقل يدوي |
| 7 | `automation` | الأتمتة والتقارير | خلي النظام يشتغل عنك |

كل شريحة فيها: علامة باسم الجزء وأيقونته، عنوان كبير، وصف، و**4 مميزات** كل واحدة ليها عنوان وسطر شرح.

### بيشتغل إزاي

- **التشغيل التلقائي:** كل شريحة بتفضل 7 ثواني (`SHOWCASE_INTERVAL_MS` في `showcaseSlides.js`) وبعدين ينتقل للي بعدها، ولما يوصل للأخيرة يرجع للأولى.
- **التوقيت مربوط بشريط التقدم نفسه:** النقطة النشطة فيها شريط بيتملي. أول ما يكمل (`animationend`) السلايدر ينتقل. يعني اللي بتشوفه هو بالظبط الوقت الفاضل، ومفيش timer منفصل ممكن يختلف عنه.
- **بيقف لوحده لما:**
  - الماوس يكون فوق السلايدر، أو الفوكس جواه (كيبورد).
  - التاب يكون مش ظاهر.
  - المستخدم يدوس زرار الإيقاف ⏸.
- **التنقل اليدوي:**
  - النقاط: كل نقطة بتودي لشريحتها.
  - زرار السابق ‹ والتالي ›.
  - أسهم الكيبورد يمين وشمال (بتتعكس صح في العربي).
  - السحب بالصباع على الموبايل.
- **الأنيميشن:** كل ما الشريحة تتغير، أجزاءها بتطلع واحدة ورا التانية (العلامة، العنوان، الوصف، المميزات) مع fade وحركة لفوق.
- **الخلفية بتتحرك مع الشريحة:** كل شريحة ليها مكان مختلف للضوء (`light` في `showcaseSlides.js`)، فلما الشريحة تتغير، الضوء كله بينزلق لمكان جديد خلال 2.4 ثانية.

### تعديل نص شريحة

النصوص كلها في `src/locales/ar/auth.js` و `src/locales/en/auth.js` تحت:

```
showcase.slides.<id>.area        ← اسم الجزء في العلامة
showcase.slides.<id>.title       ← العنوان الكبير
showcase.slides.<id>.subtitle    ← الوصف
showcase.slides.<id>.points.<pointId>.title
showcase.slides.<id>.points.<pointId>.text
```

لازم تعدّل الملفين (عربي وإنجليزي)، وإلا `npm run check:i18n` هيفشل.

### إضافة شريحة جديدة

1. في `showcaseSlides.js` ضيف عنصر جديد في `SHOWCASE_SLIDES`:
   ```js
   {
     id: 'tasks',
     icon: ListChecks,                 // أي أيقونة من lucide-react
     light: { x: 6, y: -6, r: 8 },     // مكان الضوء: vw و vh ودرجات
     points: [
       { id: 'create', icon: Plus },
       { id: 'assign', icon: UserCheck },
       { id: 'due', icon: Clock },
       { id: 'status', icon: CheckCircle2 },
     ],
   },
   ```
2. ضيف النصوص في الملفين `ar/auth.js` و `en/auth.js` تحت `showcase.slides.tasks`.
3. خلي **4 مميزات بالظبط** عشان الشبكة تفضل متساوية (الاختبار بيتأكد من ده).
4. شغّل `npx vitest run src/features/auth`. فيه اختبار بيتأكد إن كل شريحة وكل ميزة ليها نص في اللغتين.

### تغيير مدة الشريحة

غيّر `SHOWCASE_INTERVAL_MS` في `showcaseSlides.js` (بالمللي ثانية).

## 4. الخلفية المتحركة

الخلفية CSS بالكامل (مفيش canvas ولا JavaScript بيلف في loop)، فاستهلاكها للجهاز قليل جداً. مكونة من طبقات فوق بعض:

| الطبقة | الكلاس | بتعمل إيه |
|---|---|---|
| الأساس | `.login-aurora` | تدرج من لون الخلفية `--brand-bg` مع لمسة تركواز من فوق. |
| المسرح | `.login-aurora__stage` | بيشيل كل الإضاءة، وبينزلق لمكان جديد مع كل شريحة. |
| شعاع دوّار | `.login-aurora__beam` | ضوء مخروطي بيلف دورة كاملة كل 30 ثانية. |
| 4 بقع ضوء | `.login-aurora__blob--a/b/c/d` | تركواز، كحلي، أبيض ساطع، تركواز غامق. كل واحدة بتتحرك في مسار مختلف (11 لـ 20 ثانية). |
| ضربات الفرشاة | `.login-aurora__streaks` | ملمس خطوط مائلة زي Codex، بتتحرك ببطء. |
| طبقة الهدوء | `.login-aurora__veil` | بتهدّي الضوء ورا نص السلايدر عشان القراءة تفضل مريحة. |
| حبيبات | `.login-aurora__grain` | حبيبات خفيفة بتمنع ظهور خطوط في التدرجات على الشاشات الكبيرة. |

**الألوان:** كل الألوان محسوبة من متغيرات البراند (`--brand-primary` و `--brand-accent` و `--brand-primary-l` و `--ai-text`) بـ `color-mix`. لو شركة غيرت ألوانها من **الإعدادات ← المظهر**، الخلفية بتتغير معاها من غير أي تعديل في الكود.

**الوضع الداكن:** ليه ألوان وشفافيات خاصة في نفس ملف الـ CSS (`.dark ...`).

## 5. طرق تسجيل الدخول

| الطريقة | الحالة | ملاحظات |
|---|---|---|
| اسم المستخدم وكلمة المرور | **شغالة** | `POST /api/tenant/auth/signin` |
| Google | الواجهة جاهزة، الباك اند لسه | زرار "قريباً" لحد ما تتفعل |
| Face ID | الواجهة جاهزة، الباك اند لسه | WebAuthn + رجوع لـ PIN |
| البصمة | الواجهة جاهزة، الباك اند لسه | WebAuthn + رجوع لـ PIN |

### تفعيل طريقة جديدة

لما الباك اند يجهز، ضيف في ملف `.env`:

```
VITE_AUTH_METHODS=password,google,face_id,fingerprint
```

اليوزرنيم والباسورد شغالين دايماً ومينفعش يتقفلوا من هنا. أي طريقة مش مكتوبة بتظهر بعلامة "قريباً" ومش قابلة للضغط.

### مسار البصمة / Face ID

1. المستخدم يكتب اسم المستخدم (بيتملي لوحده من آخر دخول على نفس الجهاز).
2. يدوس "التحقق بالبصمة" أو "التحقق بـ Face ID"، فيظهر طلب الجهاز.
3. لو التحقق نجح، يدخل.
4. لو فشل، أو المستخدم لغاه، أو الجهاز مش بيدعم: الصفحة بتنقل لوحدها لإدخال **PIN من 6 أرقام**، وبتكتب السبب.
5. الـ PIN بيتبعت لوحده أول ما الـ 6 أرقام يكملوا، ولو غلط بيتمسح وتظهر رسالة.

على الويب، Face ID والبصمة هما نفس التقنية (WebAuthn)، والجهاز هو اللي بيختار الحساس المناسب. الزرارين موجودين عشان المستخدم يعرف يتوقع إيه.

### مسار Google

1. الضغط على Google يطلب رابط الموافقة من الباك اند، ويحوّل المستخدم لجوجل.
2. جوجل ترجّعه على `/login?code=...&state=...`.
3. الصفحة تتأكد إن `state` هو نفس اللي اتحفظ قبل التحويل (حماية من التزوير)، وتبعت `code` للباك اند.

### محتاج يتعمل بعد كده

شاشة جوه البروفايل يسجّل منها المستخدم بصمة جهازه ويحدد الـ PIN بتاعه. ده جزء من شغل بيانات المستخدم، مش صفحة اللوجين.

## 6. رسائل الخطأ

الأخطاء بتظهر **جوه الكارت** وبتفضل ظاهرة لحد ما المستخدم يكتب تاني (مش toast بيختفي).

| الحالة | الرسالة |
|---|---|
| 401 / 422 / 400 | اسم المستخدم أو كلمة المرور غير صحيحة |
| 403، أو كود فيه `inactive` / `disabled` / `suspended` | الحساب موقوف |
| 404، أو كود فيه `tenant` | مساحة العمل غير موجودة |
| 423 | الحساب مقفول مؤقتاً |
| 429 | محاولات كتير (ولو فيه `Retry-After` بيقول عدد الثواني) |
| 500 فأكتر | خطأ في الخادم |
| مفيش رد + الجهاز أوفلاين | مفيش نت |
| مفيش رد | تعذر الوصول للخادم |

الترجمة من الخطأ للرسالة في `src/features/auth/utils/loginError.js`.

**مهم:** طلب الدخول بيبعت `skipSessionRefresh` عشان الباسورد الغلط (401) ميفتحش نافذة "الجلسة على وشك الانتهاء".

## 7. حاجات تانية في الصفحة

- **اسم الشركة:** بيظهر فوق الكارت (من الـ subdomain). مش بيظهر على localhost.
- **الرجوع بعد الدخول:** المستخدم بيرجع للصفحة اللي كان طالبها قبل ما يتحوّل للوجين، والكود بيمنع أي رابط خارجي أو الرجوع للـ `/login` نفسها (`utils/postLoginRedirect.js`).
- **تذكّر آخر مستخدم:** اسم المستخدم (مش الباسورد) بيتحفظ في `localStorage` تحت `ican-last-login` عشان يتملي في مسار البصمة.
- **تفاصيل الفورم:**
  - الـ password managers بتشتغل صح (`autocomplete`).
  - المؤشر بيبدأ في حقل اليوزرنيم.
  - المسافات الزيادة في اليوزرنيم بتتشال.
  - فيه تنبيه لما Caps Lock يكون شغال.

## 8. إمكانية الوصول

- **وصف السلايدر:** معرّف لقارئات الشاشة إنه "عرض شرائح"، وكل شريحة مكتوب رقمها ("2 من 7").
- **التشغيل التلقائي:**
  - ممكن يتوقف بزرار.
  - بيقف وقت الفوكس.
  - **مبيبدأش لوحده** عند المستخدمين اللي مفعلين "تقليل الحركة" في أجهزتهم. وعندهم كمان الخلفية والأنيميشن بيقفوا.
- **الكيبورد:** كل الأزرار ليها فوكس ظاهر، والأسهم بتتنقل بين الشرائح.
- **الحقول:** مربوطة بعناوينها ورسائل خطئها.

## 10. حاجات لسه ناقصة

- **"نسيت كلمة المرور" و"تذكرني":** مش معمولين.
- **مكان التوكن:** لسه في `localStorage`، ونقله لـ httpOnly cookie محتاج شغل في الباك اند.
- **Google والبصمة والـ PIN:** مستنيين الـ endpoints من الباك اند.
