# CustomerActivityTimeline

هذا المجلد مسؤول عن عرض سجل النشاطات الخاص بالعميل في هيئة خط زمني بصري، بدل عرض البيانات الخام فقط.

## ما الذي يفعله

### 1) CustomerActivityTimeline
- المكون الرئيسي في الخط الزمني.
- يتلقى قائمة الأنشطة في شكل مجمّع من البيانات المعالجة.
- يهيّئ:
  - الفلاتر حسب الفئة
  - البحث النصي
  - المستخدم
  - التاريخ من/إلى
  - ترتيب الأقدم/الأحدث
- يقوم بتجميع الأنشطة حسب اليوم داخل مجموعات تاريخية.

### 2) ActivityHeader
- يعرض رأس الخط الزمني مثل:
  - العدد الكلي
  - آخر نشاط تم تسجيله

### 3) ActivityFilters
- أزرار الفلاتر السريعة:
  - الكل
  - الحالات
  - الملاحظات
  - المنتجات
  - التواصل

### 4) ActivityDateGroup
- يجمع الأنشطة في مجموعة يومية واحدة.
- متى تم عرضها في شكل قائمة مرتبة حسب الوقت.

### 5) ActivityTimelineItem
- يعرض عنصر النشاط الفردي داخل اليوم.
- يضم تفاصيل النشاط، المستخدم، الوقت، والبيانات المرتبطة.

### 6) Renderers
- كل نوع نشاط له renderer خاص، مثل:
  - StatusChangeActivity
  - NoteActivity
  - InterestedProductsActivity
  - DefaultActivity
- هذا يضمن أن كل نشاط يتم عرضه بشكل مناسب حسب نوعه.

### 7) normalizeCustomerActivities
- مهمة أساسية في تحويل سجل الليد إلى شكل موحد للـtimeline.
- تلتقط:
  - النوع
  - الفئة
  - التاريخ
  - المستخدم
  - الحالة القديمة/الجديدة
  - المنتجات المهتم بها
  - ملاحظات ونصوص النشاط

## هيكل العمل

- البيانات تأتي من API أو من كائن الصف المحلي.
- يتم تحويلها عبر normalizeCustomerActivities.
- ثم يتم فرزها وتصفيةها داخل CustomerActivityTimeline.
- ثم يتم تجميعها بناءً على اليوم.
- أخيراً يختار renderer المناسب لكل نشاط.

## واجهة الفلاتر الحالية

تم تعديل تصميم الفلاتر ليصبح أكثر تجميعًا ووضوحًا:

- أزرار الفلاتر بجانب بعضها البعض.
- شريط البحث داخل حاوية مخصصة مع أيقونة البحث.
- زر الترتيب بجانب شريط البحث.
- زر التاريخ مستقل، عند النقر يفتح قائمة لتحديد date from / date to.
- يمكن مسح الفلاتر والتاريخ بسهولة.

## استخدامه

```jsx
import { CustomerActivityTimeline, normalizeCustomerActivities } from '../CustomerActivityTimeline'

const logs = await leadsApi.getLeadLog(leadId)
const activities = normalizeCustomerActivities(logs)

<CustomerActivityTimeline activities={activities} />
```

## ملاحظات مهمة

- كل نشاط يتم التعامل معه عبر model موحد حتى لو كانت بيانات API متفرقة.
- هذا يقلل الاعتماد على شكل الاستجابة الداخلي ويمنع تشتيت منطق العرض في عدة أماكن.
- تصميم التصفية يوازن بين السهولة والوضوح في واجهة المستخدم.
