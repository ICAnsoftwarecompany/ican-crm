# CustomerTableDetailsDialogs

هذا المجلد يحتوي على جميع مربعات التفاصيل والديالوجات الخاصة بجدول العملاء، ويستخدم لتوسيع تفاصيل الصفوف مثل:

- تفاصيل المنتج
- تفاصيل المصدر
- سجل أنشطة العميل / lead

## ما الذي يفعله المجلد

### 1) ProductDetailsDialog
- يعرض تفاصيل منتج واحد في نافذة منفصلة.
- يقرأ بيانات المنتج من الصف الحالي أو من البيانات المدمجة داخل الصف.
- يوضح صورة المنتج، السعر، مستوى الاهتمام، والبيانات الإضافية.
- يمكن عرض بيانات خام من المنتج كـ JSON.

### 2) SourceDetailsDialog
- يعرض تفاصيل المصدر أو القناة التي جاء منها العميل.
- يظهر اسم المصدر، نوعه، الحالة، منصة الإعلانات أو النموذج، وحقول النموذج إن وجدت.
- يقدم أيضاً المنتجات المرتبطة ومعلومات خام.

### 3) LeadActivitiesDialog
- أهم نافذة في هذا المجلد.
- تستقبل الصف الخاص بالعميل أو lead.
- تحدد leadId من بيانات الصف.
- تستدعي getLeadLog من API الخاص بالليد.
- تقوم بتطبيع بيانات النشاطات من خلال normalizeCustomerActivities.
- تجهزها في CustomerActivityTimeline لعرضها بطريقة مرتبة حسب التاريخ مع الفلتر والبحث والتفاصيل.

## معلومات التنفيذ

- يعتمد على React Query لاستخراج البيانات من API.
- يستخدم createPortal لإظهار الديالوج فوق الصفحة الحالية.
- يدعم السحب داخل النافذة وتغيير أحجامها.
- يحتوي على زر تثبيت لدعم تصفح الصفحة خلف الديالوج بدون إغلاقه.
- يعرّض اسم العميل في رأس الديالوج بشكل مباشر.

## الأوامر المهمة

- جلب سجل النشاطات من backend: leadsApi.getLeadLog(leadId)
- تحويل البيانات إلى نموذج مناسب: normalizeCustomerActivities(logs)
- عرضها: CustomerActivityTimeline

## ملاحظات مهمة

- إذا كان API لا يرجع بيانات، يتم استخدام fallback محلي من getCustomerLeadActivities(row).
- إذا فشل التحميل، يظهر نص خطأ مناسب داخل الديالوج.
- يظل الأرشيف من الأنشطة قابلاً للتصفية حسب الفئة، التاريخ، المستخدم، والبحث النصي.
