عشان تشوف الشغل فعليًا على الفرونت، محتاج 3 حاجات: تثبيت المكتبات، ملف إعداد الـ Echo، وHook يسمع للتغييرات ويحدّث الجدول تلقائيًا.## 1. التثبيت## 2. ملف إعداد الـ Echo (مرة واحدة في المشروع كله)## 3. الـ Hook — بيسمع للتغييرات ويحدّث الـ Rules تلقائيًا## 4. مثال استخدام كامل — جدول عملاء بتحديث لحظي## خطوات التشغيل بالترتيب

1. **ثبّت المكتبات** (`install.sh`):
   ```bash
   npm install laravel-echo pusher-js
   ```

2. **أضف متغيرات Vite في `.env` بتاع الفرونت** (لو مش موجودة):
   ```
   VITE_REVERB_APP_KEY=your-app-key
   ```

3. **حط `echo.js`** في مسار مشترك (زي `src/lib/echo.js`) — بيتعمل import منه مرة واحدة بس.

4. **استخدم الـ Hook** بدل الـ Hook القديم (`useTableFormatRules`) في أي صفحة عايز فيها Real-time:
   ```jsx
   const { rules, connectionStatus } = useTableFormatRulesRealtime('customers', tenantId);
   ```

## اختبار سريع إن الشغل فعلاً لايف

1. افتح صفحة العملاء في **تابين مختلفين** من نفس التانت (أو مستخدمين مختلفين).
2. من التاب الأول، عدّل قاعدة `shared` (من الـ Rule Builder).
3. التاب التاني المفروض يتحدّث **فورًا من غير أي Refresh** — ولو باين جنب الجدول نقطة خضرا "التحديث اللحظي شغال"، يبقى Reverb متصل صح.

---

**ملحوظة مهمة:** لاحظ في الكود إني استخدمت `.rule.changed` (بنقطة قبل الاسم) في `channel.listen()` — دي مش غلطة، لأن الـ Event بتاعك معرّف بـ `broadcastAs()` بدل الاسم الافتراضي بتاع الكلاس، فلازم النقطة عشان `laravel-echo` يفهم إنه اسم مخصص (custom event name) مش namespace كامل.

عايز نضيف كمان **Toast Notification** بسيطة تظهر لما حد تاني يعدّل قاعدة مشتركة، عشان المستخدم ياخد باله إن حاجة اتغيرت؟
